# 实时诊断页设计原型

问题：实时排障应以共同时间轴、异常事件，还是当前状态为主入口？

这是可丢弃的 UI 原型，保存在远程 `prototype/realtime-diagnostics` 分支：[原型 b1e2266](https://github.com/ren2019/MU5250-OpenUI/commit/b1e2266)、[选择 A 的记录 ec00635](https://github.com/ren2019/MU5250-OpenUI/commit/ec00635)。实现分支已删除原型源码、切换器及启动器，保留截图作为设计证据；未部署设备。

## 启动与比较

在原型提交 `b1e2266` 的独立工作区中，进入 `web-app` 目录运行 `npm run prototype:diagnostics`，打开 http://127.0.0.1:8089/?demo=1&prototype=diagnostics&variant=A 。如需登录，密码填 `demo`。

启动器使用本地模拟后端（127.0.0.1:9090），已有模拟服务则复用；前端仅监听本机。原型入口只在开发环境和 localhost/127.0.0.1 下启用。

| 方案 | 核心结构 | 适合回答的问题 |
| --- | --- | --- |
| A 时间轴对照 | 七条曲线上下排列，共用时间范围、联动光标，侧栏显示变化 | 掉速时，信号、小区、温度是否同时变化？ |
| B 事件排障 | 左侧选择事件，右侧查看关键曲线和核对线索 | 某次异常发生前后有什么变化？ |
| C 实时盯盘 | 当前状态概览、紧凑指标网格、变化记录 | 现在运行如何，哪些指标开始偏离？ |

用底部左右按钮或键盘方向键循环切换，也可将 URL 的 `variant` 改为 B/C。方案切换保留当前场景、采样和时间范围；进入 B 会优先聚焦事件。输入控件内的方向键不切换方案。

共有操作：5/15/30/60 分钟窗口、暂停/继续、返回最新读数、NR/LTE 选择、模拟 CSV 导出。三个场景分别演示小区切换与掉速、温度上升、采集缺口。刷新会重置内存数据。

## 结论与边界

2026-09-18 用户选定 A「时间轴对照」。后续实现以 A 的七条联动曲线、共同时间轴及右侧变化时间线为设计依据。B、C 留作原型比较记录，不默认合并 B 的布局。这一选择确认的是页面设计；真实数据接入和设备诊断有效性仍待实现与验证。

全部曲线、事件、载波信息来自确定性的模拟数据；页面每 3 秒推进模拟采样，保留最多约 60 分钟。温度 10 秒等标注是未来采样设计目标，当前模拟器统一生成样本。真实接口支持、缓存周期及实际设备行为尚未在本原型中验证。长时间运行后，初始事件可能移出当前窗口，可切换场景重新演示。

缺失样本显示断线和“无读数”，不补零；温度与掉速同时出现不构成热降频结论。延迟、丢包、抖动明确列为待补充数据。诊断数据仅存内存，导出文件名明确包含 PROTOTYPE-simulated。
