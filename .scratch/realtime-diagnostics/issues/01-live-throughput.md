# 01: 实时速率时间轴

**What to build:** 用户从信号功能进入正式诊断页，看到持续更新的 WAN 上下行时间轴，可调整窗口、暂停及恢复；数据缺失和过期不会被误画为零。

**Blocked by:** None (can start immediately).

**Status:** implemented — 已集成；复合验收项按实际证据勾选

依据：已确认的实时诊断规格与 Prototype A「时间轴对照」；入口见[任务索引](../README.md)。

- [x] 按 Prototype A 建立正式入口和纵向曲线，保留现有认证、导航和主题；正式页面不含方案切换器或模拟场景控件。
- [x] 复用共享 dashboard 和轮询生命周期，按源时间及新鲜度记录数据；相同源时间戳不重复追加，不增加重复信号请求。
- [x] 上下行显示设备整体吞吐量；1,000,000 bytes/s 显示为 8 Mbps，合法零值正常显示。
- [x] 缺失、过期和不支持可区分；旧值标为上次读数，缺口不连线，失败后恢复不补造历史。
- [x] 默认 15 分钟，可选 5/15/30/60 分钟；仅保存最近 60 分钟内存数据，不预填历史，刷新重置并提示。
- [ ] 暂停冻结诊断缓冲与窗口，不影响其他模块需要的共享轮询；恢复、后台返回均保留真实时间间断，离开页面无新增诊断采样。
- [x] 提供共同时间光标和回到最新；按不晚于光标的有效样本取值，超过源有效期显示无有效读数。
- [ ] 通过页面＋可控 HTTP 模拟服务验证刷新、单位、窗口、缺口、暂停和生命周期；使用可控时间验证保留上限，既有测试及构建/lint 通过。


集成验证（2026-09-18）：共享源去重、暂停/保留上限由诊断模型测试覆盖，卸载与可见性由既有轮询测试覆盖；浏览器已检查刷新、零值、单字段缺失、HTTP 失败恢复、暂停及键盘回看。重复进出和后台恢复的页面复验仍留在 06。 统一代码检查与待验边界见[验收记录](../../../../docs/REALTIME-DIAGNOSTICS-ACCEPTANCE.md)。
