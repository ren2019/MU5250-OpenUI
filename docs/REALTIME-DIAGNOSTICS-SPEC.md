# 实时诊断：方案 A 时间轴对照

状态：规格草稿；页面设计与测试边界已确认，问题跟踪器及分诊流程待配置。目标标签为 `ready-for-agent`，本草稿尚未发布。

## Problem Statement

用户在 U60 Pro 出现掉速、信号波动或连接异常时，需要知道异常前后发生了什么。分散的瞬时读数无法展示吞吐量、无线质量、小区及设备温度之间的时间关系；只展示最新状态也无法回看短暂异常。接口返回的缓存或缺失值若被当成实时读数或零值，还会造成错误判断。

## Solution

在现有“信号”功能组中提供实时诊断页，采用用户选定的 A 方案：七条纵向排列的曲线共用时间范围与联动光标，右侧展示变化时间线。展示上下行速率、所选载波的 SINR、RSRP、RSRQ、基带温度及 CPU 使用率。用户可以持续观察、暂停、选择事件回看、切换时间窗口与无线载波，并导出当前窗口的数据。

页面展示可验证的读数和变化，帮助用户形成排查线索；不将同时变化直接判定为因果关系。无能力提供的指标明确显示不可用。

## User Stories

1. As an 设备使用者, I want 从现有信号功能进入实时诊断, so that 无需离开当前管理面板。
2. As an 设备使用者, I want 看到持续更新的上下行速率, so that 能发现业务吞吐量的变化。
3. As an 排障用户, I want 将所有曲线放在共同时间轴上, so that 能比较变化发生的先后顺序。
4. As an 排障用户, I want 查看所选载波的 RSRP, so that 能判断接收信号强度的变化。
5. As an 排障用户, I want 查看所选载波的 RSRQ, so that 能观察信号质量变化。
6. As an 排障用户, I want 查看所选载波的 SINR, so that 能观察干扰与噪声相关的变化。
7. As an 排障用户, I want 查看基带温度趋势, so that 能核对温升与掉速是否同时出现。
8. As an 排障用户, I want 查看 CPU 使用率趋势, so that 能识别设备负载与异常的时间关系。
9. As an 排障用户, I want 在 LTE、NR 的 PCC 和 SCC 中选择实际存在的载波, so that 不会把不同载波的读数混为一谈。
10. As an 排障用户, I want 看到制式、频段、PCI 及可用的小区标识, so that 能理解曲线对应的无线环境。
11. As an 排障用户, I want 查看最近 5、15、30 或 60 分钟, so that 能选择适合异常持续时间的尺度。
12. As an 排障用户, I want 移动光标时同步显示全部指标在该时刻的读数, so that 无需逐图寻找同一时刻。
13. As an 排障用户, I want 点击变化事件定位对应时刻, so that 能快速回看异常前后的读数。
14. As an 排障用户, I want 看到服务小区、载波和连接状态的变化记录, so that 能区分不同类型的异常线索。
15. As an 排障用户, I want 暂停诊断采集, so that 能稳定阅读当前窗口。
16. As an 排障用户, I want 恢复采集后看到真实的时间间隔, so that 不会误认为暂停期间仍有连续数据。
17. As an 排障用户, I want 一键回到最新读数, so that 能从历史回看恢复实时观察。
18. As an 设备使用者, I want 知道最后一次成功采样时间及数据是否过期, so that 能判断读数是否仍可信。
19. As an 排障用户, I want 缺失区间显示为空白, so that 不会将采集失败误认为速率或信号降为零。
20. As an 排障用户, I want 合法的零值仍正常显示, so that 能区分无流量与无数据。
21. As an 设备使用者, I want 不支持的温度或无线指标显示不可用, so that 不会看到伪造数据或错误替代值。
22. As an 排障用户, I want 载波消失后保留历史且停止追加该载波读数, so that 不会无提示地切换到其他载波。
23. As an 排障用户, I want 导出所选时间窗口的 CSV, so that 能进一步分析或保留现场记录。
24. As an 排障用户, I want 导出内容保留单位、载波身份、时间和数据质量, so that 离开页面后仍能正确解释数据。
25. As an 手机用户, I want 在窄屏上查看曲线和事件, so that 能在设备旁直接排障。
26. As an 设备使用者, I want 切到后台或离开页面时不持续增加无用请求, so that 监控本身不会给设备带来不必要负担。
27. As an 设备使用者, I want 明确看到本会话数据仅存内存, so that 能在刷新或关闭前主动导出。
28. As an 排障用户, I want 页面区分诊断线索与确认结论, so that 不会把温升或小区变化直接认定为掉速原因。

## Implementation Decisions

- 已确定采用 A 的纵向曲线及侧边事件时间线；不默认合并 B 的布局，不将 C 的指标网格作为主视图。保留现有登录、导航、主题和移动端框架。
- 七项首期指标：WAN 下行、WAN 上行、所选载波 SINR、RSRP、RSRQ、基带温度、CPU 使用率。WAN 速率为设备整体实际吞吐量，不随无线载波选择变成该载波的独立吞吐量，也不代表链路最大能力。
- 复用现有 API 客户端、共享 dashboard 数据和轮询调度。dashboard 已含信号、速率、CPU、连接及按源新鲜度，避免重复请求同一信号源。基带温度使用已有详细温度能力；不可用时明确显示不可用，不以 CPU 温度冒充。
- 现有速率字段虽然以 bps 命名，契约实际单位为 bytes/s；显示 Mbps 必须乘 8 再换算为十进制兆。RSRP 用 dBm，SINR/RSRQ 用 dB，温度用 °C，CPU 用百分比。
- 以下为实施规格建议，区别于已经验证的原型行为：前台诊断目标每 3 秒更新无线、速率与 CPU；温度目标每 10 秒。以实际源时间戳和缓存有效期为准，不能将页面刷新频率当成所有源的实际采样频率。实现时核对既有接口契约；仅在既有温度响应无法判断新鲜度时补充必要元信息。
- 每个指标样本保留采样时间、接收时间、值、来源和质量状态。已有源元信息包括采样时间、年龄、有效期、过期标志及错误；源时间缺失时只能称为接收时间，不伪造设备采样时间。相同源时间戳不重复计为新样本。
- 区分有效、缺失、过期及不支持。缓存中的旧值可以显示为“上次读数”，但不能继续铺成新的实时曲线。只在连续有效区间连线，合法零值不是缺失。各指标独立判断质量，一源失败不抹去其他有效源。
- 数据仅存内存，保留最近 60 分钟，默认显示 15 分钟。未积累满窗口时只显示已有记录，不预填历史。事件随保留窗口淘汰；数量与采样率成比例受限。
- 载波身份使用 LTE/NR、PCC/SCC 角色、频段、频点和 PCI 等实际字段；不能只用数组位置或 PCI 作为全局身份。身份发生变化时分段，避免将不同服务小区的信号连成同一连续序列。保留旧身份供历史回看；不得静默将已选择的消失载波替换为其他载波。
- 时间光标对齐所有曲线，但每项读数保留自身采样时间；选取该时刻不晚于光标的有效样本，超过该源有效期则显示无有效读数。不从未来取值，不跨缺口插值。鼠标、触摸及事件点击均可定位，提供可操作的“回到最新”。
- 事件由连续、有效且身份可比较的观测差异产生：制式、小区/PCI、载波集合、已知连接状态变化，以及采集失败和恢复。首次读数是基线，不报变化；失败与恢复间不推断中间发生了小区切换。重复缓存响应不重复生成事件。时间为观测到变化的时刻，不声称精确到无线侧实际切换时刻。
- 暂停冻结诊断缓冲和窗口；若共享数据仍被外壳使用，不停止其他模块需要的轮询。恢复时按真实时间追加，不补造暂停期间历史。后台及卸载行为沿用现有轮询生命周期，返回时标注间断。全页刷新结束当前内存会话。
- CSV 导出当前窗口中所选载波相关读数及设备级读数，使用记录行保留每项实际时间、指标、值、单位、载波身份和质量状态；事件可作为独立记录类型。缺失值留空，不写零。模拟导出必须清晰标明模拟，真实导出不包含认证信息。
- 正式入口不保留 A/B/C 切换器和模拟场景选择。模拟数据仅用于演示和测试，清楚标记且不会被真实模式自动采用。
- 窄屏将时间线排在曲线之后；保持指标名称、单位及状态可读，避免横向页面溢出。沿用项目主题，不重新设计整个管理面板。

## Testing Decisions

- 用户已确认的主测试边界：通过真实诊断页面访问可控的现有 HTTP 模拟服务。驱动响应序列并操作页面，验证用户看到的读数、趋势断点、时间定位、事件和下载内容；不以 React 状态、私有函数调用次数或 SVG 内部实现作为验收标准。
- 当前已有 API 客户端及轮询调度的 Node 测试，包括认证传递、请求重叠、旧响应丢弃、可见性切换及卸载后停止发布。保留这些回归测试，只有修改其契约时才新增针对性用例，不为诊断功能在每一层重复建测试边界。
- 页面集成覆盖正常递增数据、合法零值、部分字段缺失、单源失败、缓存过期、重复时间戳、采集恢复、无历史数据和不支持基带温度。校验 1,000,000 bytes/s 显示为 8 Mbps，避免单位混淆。
- 行为覆盖时间窗口裁剪、联动光标、点击事件、载波身份变化、消失载波历史、首次基线不报事件、暂停/恢复间断、回到最新、CSV 中时间/单位/空值/身份与可见数据一致。
- 使用可控时间验证 60 分钟保留上限及事件淘汰，无需真实等待一小时。确认多次进出页面不会导致重复诊断请求或卸载后追加样本。
- 检查桌面、390 像素窄屏、浅深主题和键盘/触摸操作。构建、lint 与既有测试通过是代码交付门槛，不替代浏览器验收。
- 真机只读验收独立于模拟验收：后续连接已获授权的设备，对照已有页面/API 确认单位、来源新鲜度、实际支持字段和连续采集。模拟数据不能证明真实设备诊断有效；不为验收主动切网、锁频、改温控或制造故障。

## Out of Scope

- 主动测速、Ping、丢包、抖动、DNS 探测及新增探测服务。
- 自动根因判定、热降频结论、预测、阈值告警、推送通知及长期无人值守监控。
- 云存储、数据库、跨会话历史、后台守护采集、多设备聚合和大规模监控平台。
- 客户端数、Wi-Fi 链路、内存等指标的全面扩展；首期聚焦选定 A 的七项指标和相关状态。
- 锁频、重连、充电、散热、重启等设备控制，以及部署或升级真实设备。
- 将原型分支直接作为生产代码整体合并，或重做现有服务端日志功能。
